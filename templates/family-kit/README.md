# Starlight Family Starter Kit v0.1

Public-safe templates and a design-only configuration example. These files do not install software, authenticate people, enforce permissions, connect accounts or actuate a device. Copy completed templates to your private family storage, never back to the public repository.

Start with `family-kit.example.json` as a configuration record, `family-charter.md` for shared practices, `emergency-contact-card.md` for an adult-reviewed offline fallback, and `curation-record.md` for one useful source. Use `contacts-review.csv` only in private storage. `physical-experience.md` records an experience design; it does not certify a device.

Retain originals and set the audience for every record. Names, child records, phone numbers, home addresses, keys, screenshots and private source URLs do not belong in public examples. A template's audience label must be enforced by the actual system before connecting an AI host; labels alone do not protect data.

Existing governed workflows are canonical in `frankxai/family-intelligence-systems/skills/`: `prepare-emergency-packet`, `capture-elder-story`, `extract-record-evidence`, `request-family-consent`, `run-succession-drill` and `compare-conflicting-claims`. They are references, not bundled/installable plugins. Check their revision and host packaging before use. No shared generic prompt grants access or release authority.

See [Family Layer architecture](../../docs/family-qr/FAMILY-LAYER.md) for platform adapters, current age constraints, public/commercial boundaries and pilot acceptance.
