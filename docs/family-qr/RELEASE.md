# Starlight Family QR: release receipt

Date: 2026-10-01. State: implemented prototype and locally tested policy helpers; not merged, deployed or customer-validated.
Base: `f33fbd9dd93208fd7ee6385f36f127ea66148d42` of `frankxai/family-intelligence-os`.

## Implemented

- `@family/auth/qr-entry`: opaque 128-bit locator generation, same-origin QR URL builder, trusted-input QR navigation policy, and consumer account eligibility helper.
- Denial covers missing/expired identity, password-only assurance, wrong tenant/member, malformed/expired/revoked locator records, unknown destination/classification, and unapproved child/teen destinations. All denied QR decisions share one generic message.
- Explicit destination allowlist; no arbitrary redirects, access token issuance, credential access or automatic owner override.
- `/q/[locator]`: dynamic generic locked page. No adapter means no access.
- Self-contained responsive synthetic HTML: parent/teen/child views, prepared source-labelled answers, values/learning cards, account register, safety architecture, SVG download and print actions.
- Four inactive QR SVG samples on the reserved `family.example.invalid` domain, with four-module quiet zones and error correction Q. ReportLab developer generator produces the same output on repeated runs.
- Provider/security research and bounded pilot architecture.

## Verification performed

- 62 policy/security cases passed using Node 24.19.0 native TypeScript stripping against the implementation files: `node --experimental-strip-types --test tests/qr/entry.node.ts`.
- The repository command uses its existing `tsx` development dependency: `pnpm test:qr`.
- Prototype JavaScript syntax check passed (`node --check`).
- Static HTML checks passed: all five panels present, all four sample QR URLs valid, generated SVGs match the manifest, no external script/image/iframe/stylesheet tags, and no unresolved template marker.
- Generator reproducibility passed: HTML/manifest/SVG hashes identical after regeneration.
- Only synthetic fixtures and a reserved placeholder domain are used. No credential file was read; no real records or private family repository were imported.

## Verification not completed

The local runtime lacks the repository's TypeScript/Vitest/Next.js dependencies, so the full monorepo typecheck, existing tests and Next.js production build were not run locally. Run them in repository CI before merge.

The Playwright smoke harness is supplied, but browser execution was not available: no Chromium binary was installed and the supported installer returned invalid/truncated archives. Therefore responsive visual appearance, interactions, accessibility, print layout and independent QR scan decoding are not reported as verified. The QR samples are structurally generated by ReportLab; no real-device scan is claimed. CI or a normal development machine must run the harness and scan printed cards before activation.

No independent reviewer or penetration test has approved this slice. Review of code and boundaries was performed by the implementing agent only.

## Production blockers

Verified per-person authentication and lost-device recovery; deployment-owned QR/ACL repository; resource-scoped and database authorization; private storage and malware scanning; persisted bounded audit; provider-under-18 review for any API service; required response headers/rate limits; permission-filtered retrieval; encrypted export and tested restore; device filtering evidence and privacy review.

Do not claim enforced parental controls, live monitoring, attack prevention, E2EE, GDPR compliance or real retrieval from this prototype. A routing policy helper does not validate session authenticity or replace a trusted authorization service.

## Rollback and support

Revert the QR commit; existing portal behavior is unchanged. No migration, connected service, runtime secret or family dataset is modified. Printed demonstration cards remain inert. Once real issuance exists, revoke the server locator record before removing a card; a removed card may still have been photographed.

Maintain the family module in this repository. Keep real tenant configurations, family records, scan/audit fixtures and screenshots outside public source. Review provider policies and dependency advisories before each live pilot change.
